# コードレビュー手順

コーディングエージェントがC++コードのレビューを依頼されたときの手順と報告形式。
判断基準は [coding-standards.md](coding-standards.md)（以下「規約」）とする。

## 対象の決め方

- 指定がなければ、現在のブランチの変更差分（`git diff main...HEAD` と未コミットの変更）を対象とする。
- ファイル・ディレクトリの指定があれば、そのファイル全体を対象とする。

## 観点（重大度の高い順）

1. **実バグ** — ロジック誤り、未初期化（`{}` の付かない集成体の宣言を含む）、バッファ溢れ、
   ダングリング参照、リソースリーク、境界値の誤り。
2. **C++14 以降の機能の混入**（規約0章）— 使用禁止表の機能、クラスの `static constexpr` メンバを
   `.cpp` の定義なしで参照渡ししている箇所（C++11 ではリンクエラーになり得る）。
   コンパイラが検出しない機能があるため、下記「C++11 準拠の確認」を必ず行う。
3. **組込み特有の問題**（規約10章）— `loop()`・毎フレーム処理での動的確保や `String` 連結、
   ブロッキング `delay()`、スタック上の大きなバッファ、割り込み共有変数の扱い。
4. **設計・責務の逸脱**（規約11章、[architecture.md](architecture.md)）— モジュールの依存方向の違反
   （例: `GazeController` が Arduino/M5Unified を include する）、サンプルアバターのパーツ名・座標の
   ハードコード、パーツ名からの役割推測、先回りの抽象化。
5. **規約違反（MUST / MUST NOT）** — 命名（`try` / `is` 等の接頭辞を含む）、ファイル構成、`const`、
   マジックナンバー、`#define` 定数、`enum class`、`nullptr`、`explicit` / `override`、
   生 `new` / `delete`、例外の使用、Cスタイルキャスト、波括弧の省略、エラーの握りつぶし、
   コメントの言語と内容（WHATではなくWHY）。
6. **規約違反（SHOULD）・軽微な指摘** — 関数の長さ・引数の数・ネストの深さ、`auto` の使い方、
   `final` の付け忘れ、Doxygen コメントの有無など。

## C++11 準拠の確認

core 2.x の GCC は `-std=gnu++11` でも一部の C++14/17 の機能を通してしまう（規約0章）。
次の3段で確認する。

1. **ビルド**: `pio run` が通ること（標準ライブラリの C++14/17 機能はここでエラーになる）。
   ビルドできない状況なら、その旨を報告に書く。
2. **警告**: `lib/` の自作モジュールと `src/` から出る警告が無いこと（構造化束縛・`if constexpr`・
   `if (init; cond)`・初期化キャプチャは警告だけで通る）。
3. **検索**: 以下はコンパイラが何も出さないため、`lib/` の自作モジュールと `src/` を検索して確認する。

| 検出する機能 | 検索パターン（正規表現） |
|---|---|
| ネストした名前空間 | `namespace\s+\w+::` |
| 2進数リテラル | `\b0[bB][01]` |
| メッセージなし `static_assert` | `static_assert\s*\([^,]*\)\s*;` |
| C++17 の属性 | `\[\[\s*(nodiscard\|maybe_unused\|fallthrough)` |

## 既存コードの扱い

既存コードは規約制定前の旧スタイルで書かれている（規約「適用範囲と既存コードの扱い」）。

- 追加・変更された行の違反は通常どおり指摘する。
- **C++14 以降の機能（規約0章）は既存コードでも指摘する**（全コードに適用されるため）。
- 変更範囲外にあるその他の既存違反は、**修正を求める指摘に混ぜず**、報告末尾の「既存違反（参考）」に
  種類ごとに要約して載せる（例: 「`lib/GazeController/` 全体: インデント4、メンバ末尾 `_` なし」）。
  ファイルごと・行ごとに列挙しない。
- 既存ファイル内の変更で、フォーマットがそのファイルの既存スタイルに合わせてある場合は違反としない。

## やらないこと

- レビュー中にコードを修正しない（修正は依頼があった場合のみ別作業として行う）。
- 変更範囲外の既存違反を一括で直すよう求めない。
- `platformio.ini` の C++ 規格（`-std=`）の変更を提案しない（規約で C++11 に固定している）。

## 報告形式

重大度順の箇条書きで、各指摘を次の形で書く。指摘が無ければ「問題なし」とだけ報告する。

```
- [重大度] ファイルパス:行番号 — 指摘内容（一文）。根拠: 規約 N章 / architecture.md 等
```

- 重大度は `バグ` / `C++11` / `組込み` / `設計` / `MUST` / `SHOULD` のいずれか（上の観点1〜6に対応）。
- 修正方法が自明でない場合のみ、修正案を一文添える（修正コードは書かない）。
- 「C++11 準拠の確認」の3段それぞれの結果（実施したか・問題の有無）を一行ずつ書く。
- 最後に「既存違反（参考）」を上記の要約形式で付ける（該当があれば）。
