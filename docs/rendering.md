# 描画方針

- 顔グラフィックは **画像アセット（透過PNGのパーツ分割）方式**。フルカラーのキャラクター顔を
  パーツごとのPNGに分け、フラッシュの LittleFS 領域から読み込んで重ね合成する。
- 合成は **オフスクリーンの `M5Canvas`（PSRAM上に確保した 320x240 のスプライト）** 上で行い、
  Zオーダー順に各パーツを `drawPngFile` で重ねてから `pushSprite` で一括転送する。M5GFX の PNG 描画は
  ピクセル単位のアルファ合成に対応するため、透過部分は下のパーツへ自然になじむ。
- 元パーツは 750x750 の同一キャンバス上に配置されているため、全パーツを同じ倍率・同じ原点で描くと
  位置が揃う。LittleFSへ焼くPNGは最終表示サイズ(384px)へ事前縮小しておき、実行時は等倍で描く（後述）。
- まばたきは `EyeLid`（閉じ目）パーツの重ねで表現する（実装済み）。開いた顔と閉じた顔の2枚を
  起動時に PSRAM へ事前合成し、実行時はスプライトを差し替えるだけで軽量に切り替える。`EyeLid`
  アセットは半開き位置で描かれているため、閉じ状態では瞼を下げて目全体を覆う。
- 視線移動は `Eye`（瞳）パーツの描画位置オフセットで表現する（実装済み）。視線制御は「**追従先の
  座標(点)を受け取り、そこへ視線を向ける**」責務に純化してある: `FaceRenderer::lookAt(x, y)`（画面px）で
  追従先の点を与えると、目の中心からの方向を可動域で正規化し、各パーツのオフセットへ写像して滑らかに
  追従する。この計算は `GazeController`（`lib/GazeController/`）が持ち、入力源(IMU/タッチ/通信)にも
  描画方法にも依存しない（他プロジェクトへフォルダごと流用できる境界）。`FaceRenderer` は求まった
  オフセットで描くだけ。プリミティブ図形描画は補助UIに限定する。
  - 入力は「画面上の点」を返すモジュール（`TouchInput` / `ImuInput`）に分かれ、`EyeTracker` がその中から
    追従先を1つ選ぶ。**タッチした位置へ視線が向く**（タッチが優先。離した後も一定時間その点を見続けて
    から傾きへ戻る）。
  - `ImuInput` は傾きを画面上の点へ変換する。**左右** ← `ax`（左右の傾き）、
    **上下** ← `az`（前後の倒し＝画面法線方向の重力成分）。縦に立てる＝正面 / 横に寝かせる＝下 /
    逆さ＝上。IMU軸と目線の対応・調整用定数の詳細は
    [spec/face-avatar/eye-tracking.md](../spec/face-avatar/eye-tracking.md) を参照。
- 傾きに合わせて動くのは瞳だけではない。同じ向きへ、**白目・眉（目グループ）**は控えめに、
  **鼻・口・眼鏡**はさらに小さく寄る（顔全体がわずかに傾きへ追従して見える）。可動域はいずれも
  目まわりの小領域（バンド）に収まるため、実行時はそのバンドだけを再合成する（下記の性能特性を参照）。
  Z順は `Hair → Glasses → Eye → FaceBase` / `Mouth,Nose → FaceBase` を保つ（髪は眼鏡・眉の上）。

## 性能特性と描画アーキテクチャ（実測に基づく）

- M5GFX の `drawPng` は**拡大デコードが低速**（拡大パスは 1×1 塗り）。等倍(scale=1.0)描画は約3倍速い。
  実測: 1レイヤーの拡大デコード ≈ 170ms、等倍 ≈ 60ms。全レイヤー拡大再合成 ≈ 2秒。
  → LittleFSへ焼くアセットは**最終表示サイズ(240 × zoom)へ事前スケール**して等倍描画する（zoom を
  焼き込み。マスター素材から `tools/build_avatar.py` で生成）。
- 毎フレームの全レイヤー再合成は不可能（遅すぎる）。そこで起動時に**2枚を事前合成**する:
  - `bgFull`: 開いた顔（定義ファイルの `faces.open`）。
  - `faceClosed`: 目を閉じた顔（`faces.closed`）。瞼など `show: closed` のレイヤーを、定義の重ね順
    （現在のアバターでは眼鏡・髪より下）で焼き込む。
- 実行時は状態変化時だけ描画する:
  - **視線移動のみ**: 動くパーツの可動域を囲む**小領域(バンド)だけ**を更新する。全画面(320x240)を毎回
    転送すると約55ms/回と重いため、バンドだけを「下地コピー→各段を合成→バンドだけ転送」する。
  - **開閉切替（まばたき）**: 全画面更新。閉じ=`faceClosed` を転送、開き復帰=`bgFull`+バンドを合成。
- バンド内で重ねる段（動くグループ・その上に重ね直す固定レイヤー）は PNG ではなく**生ARGBデータ**
  `stage_*.bin`（ツールが正しくアルファ合成して切り出し済み）を起動時に PSRAM へ読み込み、
  `pushAlphaImage` で合成する。毎フレームのPNGデコード（約60ms）を避けられ、`drawPng` がスプライト宛に
  半透明のアルファを保持しない問題も回避できる。
- どのパーツをどう重ね・どう動かすかはアバター定義ファイル `avatar.json` が持ち、描画コードは特定の
  パーツ名や座標を持たない（[avatar-definition.md](avatar-definition.md)）。
- アセットは**実ファイル**として持つ（画素をC++ソースへ配列化しない）。フラッシュの**LittleFS領域**
  (`/assets/avatar/`)から読み、`AssetLoader` がマウントとパス解決を担う。
  `tools/build_avatar.py` で `data/` を生成し `pio run -t uploadfs`
  でフラッシュへ書き込む（詳細は [build.md](build.md) / [tools/README.md](../tools/README.md)）。
- 瞳は白目(EyeBase)の内側にほぼ収まり、その領域には上位レイヤーの不透明画素がほとんど無い（実測:
  白目マスク約10,000px 中それぞれ 30〜40px 程度）ため、背景の上に瞳を描いても描画順は破綻しない。
  視線移動時のはみ出しは、**左右それぞれの白目の外接矩形**へクリップして防ぐ（左右は鼻筋で分かれて
  いるため、単一矩形だと隙間へはみ出す）。

画像アセットとM5GFXプリミティブ描画の具体的な使い分け、表情ごとのパーツ構成・状態遷移・
視線トラッキングなど実装レベルの詳細は [spec/face-avatar/README.md](../spec/face-avatar/README.md) を参照。
